The three engines

A knowledge graph and a vector engine — one custom-built system

Other products make you choose: a knowledge graph (great at "how does this connect?") or a vector database (great at "what’s similar to this?"). SKATE is both, built as one custom engine (plus plain keyword search) with no database servers to run. Knowledge is typed the moment it exists, linked by relationships a human approved, and found by meaning, keyword, and connection at once.

Traceable

FAQ

Fair questions, straight answers

Isn't this just another note-taking app?
No — notes are the input, not the product. A note app stores prose; SKATE types it, links it, governs it, and retrieves it as bounded evidence an AI can reason over. The difference shows up six weeks later, when "why did we decide that?" gets a cited answer instead of archaeology.
What if I don't have an AI key — or don't want one?
SKATE works with OpenAI, Anthropic, OpenRouter, a local LM Studio model, or nothing at all. The deterministic synthesis produced a full ranked readout in 11 milliseconds with zero AI. Providers are a dial, not a dependency.
Where does client data actually live?
In plain Markdown files on the machine running SKATE — readable in Notepad or Obsidian, versionable in git, portable forever. No database, no cloud sync, no telemetry. Cloud AI touches only the bounded evidence payload, and only when you've explicitly chosen a cloud provider.
Why not mem0, Zep, or just a plain vector database?
Mem0 and Zep are good products aimed at a different job: giving a chatbot per-user memory, with an LLM deciding what's worth keeping. SKATE keeps the actual words, lets humans govern what becomes fact, and is built and benchmarked for long prose. As for vector databases: SKATE already has vector search built in. What a plain vector database lacks is everything SKATE wraps around those vectors, the typed graph that records how evidence connects, so "what's similar?" also comes with "why, says who, and what contradicts it." Similarity alone can't answer those questions; it never recorded the links.
How do agents connect, and what can they do?
Over MCP — STDIO for Claude Desktop and Codex (one-click setup scripts included), Streamable HTTP for web surfaces. Agents get governed reads: bounded search, full memory objects, session context, evidence traces, and saved GRIND results. Writes are additive-only with agent provenance: an agent can never edit or delete existing memory, because no such tool exists.
